# 갈래 — 조원 전달 문서

Sep 30, 2026 · @기획 담당

갈래는 LLM과 긴 작업을 할 때 대화 속에 묻히는 질문 · 결정 · 산출물을, 채팅 옆 노선도로 실시간 정리해 주는 AI 에이전트예요. 빅데이터핀테크 AI응용사례 과제 Category C(업무용 AI Agent 앱, AI 적용 전후 workflow 비교, 2인 공동 발표)로 준비 중이에요.

## 한 줄 소개와 문제 정의

**한 줄 소개 (과제 등록용)** — LLM과 긴 작업을 할 때 대화 속에 묻히는 질문, 결정, 산출물을 AI 에이전트가 실시간으로 본류 · 곁길 · 수정 · 결정으로 분류해 노선도로 보여주고, 수정사항을 모아 최종본을 한 번에 요청하게 돕는 도구 (크롬 확장 프로그램 + Claude MCP).

**핵심 문장** — 채팅은 한 줄로 쌓이는데, 실제 작업은 가지를 치며 진행된다.

| 묶음 | 증상 | 근거 |
| --- | --- | --- |
| A. 흐름이 안 보인다 | 곁가지 뒤 복귀하려면 다시 읽어야 함, 전체 흐름과 결정이 묻힘 | OpenAI · Perplexity 커뮤니티의 분기 · 탐색 기능 요청 |
| B. LLM이 흐름을 잃는다 | 곁가지 내용을 계속 끌고 옴, 길어질수록 답이 나빠짐 | 여러 턴에 나눠 주면 정확도 약 40% 하락 (Microsoft · Salesforce) |
| C. 산출물이 흩어진다 | 작은 수정마다 재생성, 요청 외 변경, 파일 위치 혼란 | NBA 프로젝트 폴더: 같은 CSV 3개 버전, 발표 문서 2개 버전 |

기존 도구(ChatGPT 분기, BranchGPT 같은 트리 확장 프로그램)는 구조만 그리고 의미를 판단하지 않아요. 이 빈자리가 에이전트의 역할이에요.

## 이미 정한 것

형태, 화면, 표기 규칙, 에이전트 동작까지 정해져 있어요. 바꾸고 싶은 게 있으면 댓글로 남겨 주세요.

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 형태 | 입구 2개: 크롬 확장 프로그램(웹) + Claude 데스크톱 MCP(앱), 백엔드는 Python 하나 | 별도 채팅창을 만들면 또 하나의 LLM처럼 보여서, 기존 LLM 옆에 붙는 방식을 택함 |
| 화면 | D안: 평소엔 오른쪽 레일, 펼치면 가로 노선도 | 방해가 없고, 펼친 노선도가 ‘갈래’라는 이름과 맞음 |
| 세로 층 | 본류가 가장 아래, 1차 · 2차 곁길은 위로(레일에서는 오른쪽으로) 비켜 섬. 3차부터 접음 | 크기를 고정하려고 |
| 분화 · 복귀 | 곁길에 있는 동안 본류는 점선으로 멈춤, 돌아오면 이어 붙고 곁길은 회색으로 접힘 | 어디로 돌아가야 하는지가 보이게 |
| 긴 대화 | 지난 구간은 눈금으로 접고 지금 구간만 펼침 | 질문이 30개여도 한 화면 |
| 복합 메시지 | 요청 단위로 쪼개고, 역은 캡슐 모양(●○). 수정 요청은 대기열로, 답 못 받은 요청은 빈 칸 + 다시 묻기 | LLM이 여러 질문 중 일부만 답하는 일이 흔함 |
| 이동 | 역을 누르면 그 대화로 스크롤, 스크롤하면 ‘보는 중’ 표시가 따라옴 | 지도와 채팅이 하나처럼 동작 |
| 프로젝트 색 | 노드가 아니라 노선에만, 여러 프로젝트를 한꺼번에 볼 때만 | 노드 색은 이미 뜻이 있음 |
| 사용 유형 | U1 프로젝트 분리형 · U2 한 창 몰아쓰기형 · U3 매번 새 창형 · U4 분기 활용형에 따라 에이전트가 다르게 행동 | 적응형 에이전트 = 에이전트다움의 핵심 |

**표기 규칙** (모든 화면 공통)

- ● 검정 점 = 보통 질문
- ◯ 빨간 테두리 = 정함(결정이 난 질문)
- ● 빨갛게 채운 점 + 빛 테두리 = 지금 위치, 화면 전체에 딱 하나
- ○ 회색 테두리 = 곁길
- ■ 검은 사각형 = 산출물, v3 = 같은 파일의 세 번째 버전
- ‘보는 중’ = 검은 표시, 스크롤을 따라옴

## 보는 순서와 링크

프로토타입을 먼저 눌러보고 캔버스를 보면 30분 안에 전체가 잡혀요. 링크가 열리지 않으면 알려주세요(공유 설정 필요).

1. **프로토타입** (5분) — 갈래 프로토타입 (팀 내부 링크)
   - ‘다음 턴 ▶’: 대화가 이어지며 지도가 갱신됨. 5턴째에 곁길에서 본류로 복귀
   - 역 · 레일의 점 클릭: 해당 대화로 이동, 스크롤하면 ‘보는 중’이 따라옴
   - 03 캡슐 역과 ‘빠진 요청 다시 묻기’, ‘수정 1건 모아둠’
2. **화면 캔버스** — LLM 질문 정리 에이전트 화면 (팀 내부 링크), 위쪽 페이지 목록에서 고름
   - **기본 구상** (5분): 최신 화면 4장. 메인 · 모아둔 것 · 역 상세 · 접힌 상태
   - **사용 유형별** (5분): U1–U4에 따라 달라지는 노선도
   - **구조** (5분): 시스템 구조도 + 에이전트 내부 과정(요청 분해 → 분류 → 붙일 자리 → 답변 점검)
   - 선택: **예시 · NBA 프로젝트**(과거 대화 불러오기 · 산출물 탭), **재설계**(디자인 탐색 기록, 프로젝트 전체 지도 포함)
3. **이 문서의 나머지** (10분) — 아직 안 정한 것, 역할, Git 구조

## Git 저장소 구조와 협업 방식

저장소 하나에 입구(extension, mcp)와 백엔드를 폴더로 나누고, 둘이 주고받는 데이터 형식을 먼저 정해서 따로 작업해도 붙게 해요.

```
galrae/
├─ README.md            실행 방법, 화면 링크
├─ docs/
│  ├─ overview.md        문제 정의 · workflow 비교 (이 문서 내용)
│  ├─ schema.md          역 · 요청 · 산출물 데이터 형식  ← 가장 먼저
│  └─ survey.md          사용 양식 설문
├─ prototype/
│  └─ index.html         지금 프로토타입 (화면 기준점)
├─ extension/           크롬 확장 프로그램 (Manifest V3)
│  ├─ manifest.json
│  ├─ content/           채팅 화면 읽기 (사이트별 모듈)
│  │  ├─ claude.js
│  │  └─ chatgpt.js
│  └─ panel/             레일 + 가로 노선도 (prototype에서 옮겨옴)
├─ backend/             Flask
│  ├─ app.py             /turns API
│  ├─ agent/
│  │  ├─ split.py         ① 요청 분해
│  │  ├─ classify.py      ② 분류  ③ 붙일 자리
│  │  └─ check.py         ④ 답변 점검
│  ├─ prompts/           분류 프롬프트 (글로 관리)
│  ├─ store.py           SQLite
│  └─ .env.example       API 키 자리 (실제 .env는 올리지 않음)
├─ mcp/                 Claude 데스크톱용 MCP 서버 (선택)
└─ eval/                분류 정확도 평가용 정답 라벨
```

**가장 먼저 합의할 것: docs/schema.md.** 프로토타입의 데이터 형식을 그대로 계약으로 쓰면 돼요. 확장 프로그램은 이 형식을 받아 그리고, 백엔드는 이 형식으로 돌려주면 둘이 따로 만들어도 맞물려요.

```json
{"id": "n4", "depth": 0, "parent": "n2", "title": "LASSO냐 Ridge냐",
 "decision": "Ridge 채택", "files": ["선수명단_입력피처.csv"],
 "parts": [{"text": "VIF 표 만들기", "type": "task", "answered": false},
           {"text": "01 식 이름 바꾸기", "type": "revision", "target": "n1"}],
 "ref": null, "messageId": "<채팅 화면의 메시지 위치>"}
```

**협업 방식**

1. `main`은 항상 시연 가능한 상태로 둠. 직접 push하지 않음
2. 작업마다 브랜치: `feat/extension-rail`, `feat/backend-split`, `docs/survey`처럼 한 기능 하나
3. 커밋 메시지는 `feat:` `fix:` `docs:` `refactor:` 앞머리 + 한 줄 한국어 설명
4. Pull Request를 열고 상대가 확인한 뒤 merge. 화면이 바뀜 PR은 스크린샷 첨부
5. 바뀜 여지가 많은 파일(`docs/schema.md`, `prototype/index.html`)은 손대기 전에 한마디 하고 작게 나눠 커밋
6. API 키가 든 `.env`는 `.gitignore`에 넣고 절대 올리지 않음

첫 커밋은 지금 가진 프로토타입 파일(`index.html`, `README.md`)과 이 문서를 docs/로 옮긴 것이면 충분해요.

## 디자인 고도화 방향

구조(레일 + 가로 노선도, 표기 규칙)는 유지하고, 서비스처럼 보이게 하는 요소를 더해요. 우선순위는 아이콘 → 다크 모드 → 대표 움직임 순이에요.

| 요소 | 할 일 | 기준 |
| --- | --- | --- |
| 아이콘 · 워드마크 | 분기점이나 정렬을 담은 심볼, ‘갈래’ 두 글자 다듬기 | 툴바 16px에서도 알아봄, 라이트 · 다크 둘 다. 특정 서비스 로고를 닮지 않게 |
| 이름 체계 · 말투 | 역 · 노선 · 지선 · 환승 · 종점 · 이음매 용어를 화면 문구 전체에 | 해요체, 한 줄. 실제 교통 기관의 배지 · 로고는 가져오지 않음 |
| 다크 모드 | 모든 색을 토큰으로, 옆 사이트 테마를 감지해 따라감 | 틀은 사이트에 녹아들고, 브랜드는 지도에서만 |
| 색 체계 | 프로젝트 노선색 6–8개 추가 | 색끼리 밝기 차이, 빨강 · 초록 조합 피함, ‘테두리 = 정함, 채움 = 지금’ 유지 |
| 대표 움직임 | 새 질문이 들어오면 선이 그어지며 역이 생김, 분기와 복귀 장면 | 한 순간에 집중, 움직임 줄이기 설정 존중 |
| 첫 사용 경험 | 3단계 안내(지금 위치 → 정함 → 눌러보기), 빈 상태 화면 | 범례 없이도 이해되게 |
| 밖에서 보이는 모습 | 웹스토어 스크린샷, 소개 페이지 + 시연 GIF, ‘내 프로젝트 노선도’ 이미지 내보내기 | 공유하고 싶어지는 결과물 |

**다른 도구나 디자이너에게 맡길 때의 브리프**

- 고정: 레일 + 가로 노선도 구조, 표기 규칙, 빨강은 ‘지금 · 정함’에만
- 바꿔도 됨: 글꼴, 중립색 톤, 아이콘, 모션, 여백
- 참고 방향: 교통 안내 체계, 스위스 지도 디자인, 한글 타이포그래피
- 피할 것: 보라 · 파랑 그라데이션, 둥근 카드 남발, 이모지, ‘AI 반짝이’ 아이콘

**심볼 (논의 중)** — 사방으로 흩어진 선들이 떨어지며 작은 원을 중심으로 정렬되는 모양. ‘흩어진 답변을 정렬한다’는 뜻을 담고, 세련된 형태와 애니메이션은 이후 확정.
