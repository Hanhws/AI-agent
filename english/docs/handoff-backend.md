## 0. 먼저 알아 둘 것

### 0-1. 서버도 DB도 사지 않아요

가닥은 **각자의 PC 안에서 돌아요.** 우리 서버에 대화를 모으지 않아요.

```
[내 PC]
  Claude Code · Codex 기록 파일 ─┐
  크롬 확장 (Claude · ChatGPT 웹) ─┼─▶ 가닥 백엔드 (Flask, 127.0.0.1:7311) ─▶ ~/.gadak/gadak.db (SQLite, 파일 하나)
  Cursor hook ───────────────────┘          │
                                            └─▶ 분류할 때만 그 턴을 LLM으로 (사용자 본인의 Claude 구독)
[팀 서버] server/  ◀── 동의한 사람의 사용 기록만 (숫자 · 참거짓 · 정해 둔 낱말. 대화 글은 안 감)
```

- DB는 SQLite 파일 하나예요. 설치하거나 살 것이 없어요.
- 대화 원문은 각자 PC에만 있어요. 그래서 우리가 대화를 모아 보안을 책임질 일이 없어요.
- 팀 서버(`server/`)는 사용 기록만 받아요. 받을 수 있는 칸은 `backend/usage_schema.py`의 표가 전부예요.

### 0-2. 학습 데이터 없이 추천하는 ‘알고리즘’은 이미 있어요

“학습 데이터 없이 사용자가 생각 못 한 것을 짚어 주는 것”이 가닥의 2단이에요. 모델을 학습시키지 않고, **그 사용자의 대화 자체를 LLM이 읽고 판단**해요.

| 단계 | 하는 일 | 파일 |
|---|---|---|
| 1단 · 분류 | 턴 6~8개를 묶어 LLM에 한 번 물어요. 본류/곁길(`depth`), 정한 것(`dec`), 요청 나누기(`parts`) | `backend/agent/classify.py` · `backend/prompts/classify.txt` |
| 2단 · 확인 | 1단에서 걸린 턴만, LLM이 도구(지난 턴 읽기 · 바뀐 파일 보기 …)를 골라 쓰며 확인하고, 맞으면 할 일(Item)로 올려요. 판단 기록을 남겨요 | `backend/agent/investigate.py` · `backend/agent/tools.py` · `backend/prompts/investigate.txt` |

할 일의 종류는 `docs/schema.md`의 Item `kind` 표에 있어요(빠진 요청 · 요청 외 변경 · 다음 할 일 …). “생각 못 한 방법 추천”은 이 표에 종류를 하나 더하거나 `next`(다음 할 일)를 넓히는 일이에요 → 아래 B8.

### 0-3. MCP는 내리기로 해요 (제안)

MCP는 서버 비용이 드는 일은 아니에요. Claude 데스크톱이 각자 PC에서 띄우는 작은 프로그램이고, 받은 턴을 내 PC의 가닥으로 넘길 뿐이에요. 그래도 내리는 까닭은 이것이에요.

- `record_turn`을 부를지는 Claude가 정해서, 턴이 빠질 수 있어요.
- Claude가 매 답마다 대화 전문을 도구 인자로 다시 써야 해서, 사용자의 Claude 사용량을 먹어요.
- 데스크톱 앱의 대화는 claude.ai에도 있어서, 크롬 확장이나 내보내기 파일로 읽을 수 있어요.

→ 발표에서는 “Claude 데스크톱은 웹 · 내보내기로 읽음”으로 밝혀요. README 9장 MVP의 ‘입구 넷’은 팀에서 한 번 정하고 고쳐요. (빈 브랜치 `feat/mcp`가 있는데, 내리면 지워요.)

### 0-4. 시작하기

```bash
git fetch && git switch docs/survey-17      # 지금 가장 최신 가지 (PR #4)
python3 -m venv .venv && ./.venv/bin/python -m pip install -r requirements.txt

```

- 작업마다 가지를 따로 내요(`feat/…` · `fix/…`). `main`에 직접 push하지 않아요.
- 커밋: `feat:` `fix:` `docs:` `refactor:` + 한 줄 한국어.
- **먼저 사람에게 묻고 바꾸는 파일**: `docs/schema.md` · `prototype/` · `backend/prompts/`. 사용 기록 칸(`backend/usage_schema.py`)과 자동 실행 종류(`store.AUTO_KINDS`)도 마찬가지예요.
- 규칙 전체는 `CLAUDE.md`, 구조는 `README.md`, 쓰는 법은 `docs/usage-guide.md`.

## 1. 작업 목록

### B1. 정확도 평가 — 10/6~7 · 가장 먼저

- **왜**: 발표에 “실제 대화 58턴에서 depth 정확도 n%, 결정 재현율 n%”가 들어가요. 1단을 어느 모델로 돌릴지도 이 숫자로 정해요.
- **지금**: `eval/` 폴더가 없어요. 정답 파일 `data/example_conversations.json`(실제 대화 u1, 58턴)은 공개 저장소에서 뺐어요 → **팀 내부 링크에서 받아 같은 자리에 두고, 커밋하지 마요.**
- **할 일**
  1. 평가 예시 겹침 정리 — `docs/agent-prompt.md` 3장의 예시 셋이 u1에서 나왔어요. 그 턴을 평가에서 빼요.
  2. 정답 일치율 — 둘이 따로 u1의 10~20턴에 정답을 달고 서로 얼마나 맞는지 봐요.
  3. `eval/` 스크립트 — `backend/replay.py`로 u1을 흘려보내고, 정답과 견줘 숫자를 내요.
     지표: depth 정확도 · dec 재현율 · parts 개수 일치율 · items 정밀도(쓸데없는 한마디 비율).
  4. 모델 비교 — 기준선을 큰 모델로 재고, Haiku가 비슷하면 1단은 Haiku로 (`GADAK_ENGINE_MODEL`).
- **다 됐다**: `python -m eval` 한 번에 위 네 숫자가 나오고, 결과를 README에 적음.

### B2. 웹 데모 배포 — 10/7 · 제출 링크

- **왜**: 제출물이 ‘저장소 · 영상 + 배포 웹 데모’예요.
- **지금**: 가닥 창은 `?demo`로 만든 예시를 띄울 수 있어요(`data/demo_conversations.json`). 서버에서는 구독 엔진을 쓸 수 없어서, **미리 분류해 둔 예시만** 보여 주기로 했어요(10/3 결정).
- **할 일**: 가닥 창 + 예시 데이터를 정적 사이트로 묶어 무료 호스팅(GitHub Pages · Vercel 등)에 올려요. 백엔드 API가 없어도 돌게, 데모 모드에서 쓰는 응답을 JSON 파일로 내려 둬요.
- **주의**: 실제 대화(u1)가 든 파일은 올리지 않아요. 디자인 개편이 들어오면 다시 올려야 하니, 올리는 과정을 스크립트 하나로 만들어 둬요.
- **다 됐다**: 주소 하나로 누구나 노선도 · 할 일 · 판단 기록을 눌러 볼 수 있음.

### B3. 왼쪽 목록에 `scratch-…`가 프로젝트 이름으로 나오는 것 — **10/6 프론트 담당이 끝냄** (`store.folder_project`, ‘폴더 없는 대화’로 묶음 · 예전 DB는 열 때 옮김)

- **왜**: Claude 데스크톱 앱에서 폴더 없이 연 세션은, 앱이 만든 임시 폴더(`…/Claude/scratch-workspaces/<id>/<id>/scratch-2026-10-06-a1a600`)에서 돌아요. 가닥은 폴더 이름을 프로젝트 이름으로 써서 이게 그대로 보여요.
- **고칠 곳**: `backend/sources/sync.py:18` — `store.project_key(Path(cwd).name)`
- **할 일**: 경로에 `scratch-workspaces`가 들어 있으면 ‘폴더 없는 대화’ 같은 한 프로젝트로 묶어요. 문구는 프론트 담당과 맞춰요. 이미 DB에 들어간 프로젝트 이름도 바뀌게(다시 읽기 또는 이름 고치기) 해요.
- **다 됐다**: 테스트 하나(`tests/test_backend.py`에 scratch 경로 → 묶인 이름) + 가닥 창 왼쪽에서 확인.

### B4. 노선도 창을 ESC로 접기 — 작음 · Swift

- **왜**: 떠 있는 버튼으로 연 위쪽 노선도 창을 키보드로 바로 닫고 싶어요.
- **지금**: ESC 처리는 있어요(`mac/Float.swift:316`). 그런데 **노선도 창이 키 창일 때만** 받아요. 창을 열 때 `orderFrontRegardless()`(`mac/Float.swift:650`)로 띄워서 키보드는 원래 쓰던 앱에 남아 있고, 그래서 ESC가 가닥으로 오지 않아요.
- **할 일 (둘 중 하나)**
  - 쉬운 길: 창을 열 때 키 창으로 만들어요(패널이 키를 받을 수 있게 하고 `makeKey()`). 열린 동안은 키보드가 노선도 창으로 와요.
  - 어디서든: 전역 키 감시(`NSEvent.addGlobalMonitorForEvents`). macOS ‘손쉬운 사용’ 권한을 사용자가 허락해야 해요.
  - → 쉬운 길을 추천해요. 권한 창은 첫인상을 해쳐요.
- **다 됐다**: 다른 앱을 쓰다가 버튼 → 노선도 창 → ESC로 닫힘. 닫은 뒤 원래 앱으로 키보드가 돌아감. `mac/FloatCheck.swift`에 확인 한 줄.

### B5. 설치하면 바로 켜지는 앱 — 큼 · 10/10 기능 동결 전

- **왜**: 지금은 `가닥 설치.command`가 Python 가상환경을 만들고, Swift로 앱을 그 자리에서 빌드해요(Xcode 명령어 도구 필요). 앱은 **저장소 폴더의 코드**를 돌려서, 폴더를 옮기면 다시 설치해야 해요. 개발자가 아니면 쓰기 어려워요.
- **목표**: dmg를 받아 응용 프로그램 폴더로 끌어 넣고 → 켜고 → (구독이 없으면) API 키를 한 번 넣으면 끝. 터미널 없음.
- **할 일**
  1. Python과 백엔드를 앱 안에 넣어요. PyInstaller(또는 py2app)로 백엔드를 묶고, 지금의 Swift 겉(`mac/Gadak.swift` · `backend/macapp.py`)이 묶인 백엔드를 띄우게 바꿔요.
  2. 앱을 미리 빌드해서 dmg로 내요. 사용자 PC에서 컴파일하지 않게.
  3. 서명: Apple 개발자 계정(연 $99)이 없으면 첫 실행 때 ‘확인되지 않은 개발자’ 경고가 떠요. 과제 수준에서는 ad-hoc 서명 + 안내문 “처음 한 번 오른쪽 클릭 → 열기”로 가요.
  4. 엔진 고르기: Claude Code가 있으면 지금처럼 구독 엔진, 없으면 API 키를 받아요(B6).
- **프론트와 맞닿는 곳**: 첫 실행 화면(키 넣기 · 찾은 곳)의 화면과 문구는 프론트 담당이 만들어요. 백엔드는 API만 내요.
- **다 됐다**: Python · Xcode가 없는 Mac에서 dmg → 켜기 → 노선도까지. `docs/usage-guide.md` 1장을 새 방법으로 고침.

### B6. API 키 엔진 — B5와 같이

- **왜**: 지금 엔진은 `claude_cli`(Claude Code 구독)와 `none` 둘뿐이에요(`backend/engines/`). Claude Code가 없는 사람은 분류를 못 해요. “각자의 API 키만 넣으면 바로”가 되려면 필요해요.
- **할 일**
  1. `backend/engines/`에 Anthropic API 엔진을 더해요. `claude_cli`와 같은 모양으로 불리게.
  2. 키는 **macOS 키체인**에 저장해요. `.env`에 평문으로 두지 않아요. 키를 받고 확인하는 API(`POST /engine/key` 같은)를 내요.
  3. `auto` 고르기 순서: Claude Code 있음 → 구독 엔진 / 키 있음 → API 엔진 / 둘 다 없음 → 첫 화면에서 안내.
  4. 비용: 1단은 Haiku급이면 턴당 1센트 미만이에요(`docs/agent-prompt.md` 4장). B1 결과로 모델을 정해요.
- **다 됐다**: 키만 넣은 Mac에서 정리 · 놓친 일 찾기가 돎. 키가 틀리면 가닥 창에 한 줄로 알려 줌.

### B7. 대화를 ‘서랍’으로 요약 + ‘더 자세히 가닥잡기’로 원본 — 프론트와 같이

- **무엇**: 가닥 창 아래의 대화(지금은 원문 그대로)를 턴마다 접힌 서랍으로 보여요. 서랍에는 이 턴에서 오간 맥락이 정리돼 있고, ‘더 자세히 가닥잡기’를 열면 답변 원문이 나와요.
- **나누기**
  - 질문 쪽: 1단 결과에 이미 `title` · `parts[]`(요청 나누기) · `dec`(정한 것)가 있어요 → **새 LLM 호출 없이** 프론트가 바로 그릴 수 있어요.
  - 답변 쪽 요약: 새 칸이 필요해요(예: `turn.gist` — 답변이 던진 맥락 2~4줄). **1단 호출에 같이 실어** 호출 수를 늘리지 않아요. 출력 토큰은 조금 늘어요.
- **먼저 물을 것**: `docs/schema.md`(새 칸)와 `backend/prompts/classify.txt`(요약 지시)를 바꾸는 일이라, 칸 이름과 모양을 프론트 담당과 정하고 시작해요.
- **다 됐다**: `GET /projects/:id/view`의 턴마다 요약 칸이 오고, 예시 대화(`?demo`)에도 채워져 있음.

### B8. “생각 못 한 방법 추천” — B1 뒤에

- **무엇**: 0-2에서 말한 것처럼, 학습 데이터 없이 그 사용자의 대화를 근거로 “이런 방법도 있어요”를 짚어 줘요.
- **어디에**: 2단(`investigate.py`)에 붙이는 게 맞아요. 근거(어느 턴 · 어느 지난 대화)를 판단 기록에 남길 수 있어서요. 종류는 `next`(다음 할 일)를 넓히거나 새 `kind`를 더해요.
- **위험**: 쓸데없는 한마디가 늘기 쉬워요. B1의 items 정밀도로 재고, 기준을 넘을 때만 켜요.
- **먼저 물을 것**: `docs/schema.md`의 kind 표와 `backend/prompts/`를 바꾸는 일이에요.

### B9. 웹 입구 마무리 — 10/8~9 · 프론트와 같이
