이 README 하나에 지금까지 정한 모든 것을 최신 기준으로 담았어요. 이전 이름 ‘갈래’로 된 자료는 `archive/`에 있고, 내용이 다르면 **이 README가 이겨요**.

**10/3 갱신** — 구현 결정 다섯 가지(2단 에이전트 · 입구 넷 모두 · 배포 웹 데모 · workflow 둘 · 승인한 종류만 자동 실행)를 반영했어요. 무엇이 바뀌었고 무엇을 정해야 하는지는 `CHANGES.md`(한눈에 보는 짧은 판)에, 날짜별 상세와 문구 전체는 `docs/changes-detail.md`에 있어요. `docs/schema.md` · `docs/agent-prompt.md`는 아직 그대로이고, 거기에 필요한 변경은 상세 문서에 제안으로 적어 뒀어요.

**10/3 갱신 (2) · 켜면 알아서** — 가닥을 켜면 이 PC에서 LLM 사용 기록을 찾아 읽고(Claude Code · Codex는 알아서, Cursor는 한 번 연결, 웹 · 데스크톱 앱은 내보내기 파일), 보는 대화부터 정리해서 가닥 창에 노선도로 보여 줘요. 화면은 프로토타입의 노선도 카드 · 레일 · 목록 · 한마디를 `shared/ui/`로 옮긴 것이에요. 바뀐 곳은 `docs/changes-detail.md` 6번, 쓰는 법은 `docs/usage-guide.md`.

**10/4 갱신 · 가닥 앱** — macOS에서는 가닥이 보통 프로그램이에요. `가닥 설치.command`를 한 번 더블클릭하면 응용 프로그램 폴더에 가닥 앱이 생기고, 그 뒤로는 Launchpad · Spotlight · Dock에서 켜요. 자기 창과 메뉴가 있고, 창을 닫으면 뒤에서 돌던 것도 같이 꺼져요. 화면은 그대로예요(같은 가닥 창을 앱 창에 띄워요). 바뀐 곳은 `docs/changes-detail.md` 9번.

**10/4 갱신 (2) · 사용 기록 모으기** — 가닥을 어떻게 쓰는지 알아서 고쳐 나가려고, 동의한 사용자의 **사용 기록**을 가닥 팀 서버(`server/`)에 모으는 구조를 넣었어요. 보내는 것은 숫자와 정해 둔 낱말뿐이고(무엇을 눌렀는지, 한마디를 실행했는지, 대화의 턴 수 · 곁길 수 같은 모양), **대화 글 · 역 제목 · 파일 이름은 보내지 않아요.** 판단(분류 · 놓친 일 찾기)은 지금처럼 각자 PC에서 돌아요. 서버 주소를 정하기 전에는 아무것도 묻지도 보내지도 않아요. 바뀐 곳은 `docs/changes-detail.md` 10번.

## 2. 문제 정의

**핵심 문장: 채팅은 한 줄로 쌓이는데, 실제 작업은 가지를 치며 진행된다.**

| 묶음 | 증상 | 근거 |
|---|---|---|
| **A. 흐름이 안 보인다** | 곁길 질문 뒤 원래 흐름으로 돌아가려면 위로 스크롤해 다시 읽어야 함. “그래서 뭘로 정했지?”가 묻힘 | 설문: 곁길 뒤 스크롤 16명 중 14명 경험 · OpenAI · Perplexity 커뮤니티의 분기 기능 요청 |
| **B. LLM이 흐름을 잃는다** | 곁길 내용을 이후 답에 끌고 옴. 길어질수록 답이 나빠짐 | 여러 턴에 나눠 주면 정확도 약 40% 하락 (Microsoft · Salesforce, “LLMs Get Lost in Multi-Turn Conversation”) · 설문에서는 가장 약함(10명 ‘없음’) |
| **C. 산출물이 흩어진다** | 작은 수정마다 v1 · v2 · v3 재생성, 요청 안 한 곳까지 바뀜, 어느 게 최신본인지 모름 | **설문에서 가장 자주 아픈 문제**: 최신본 혼동 ‘자주 이상’ 8명, 요청 외 변경 6명(+가끔 7) |
| **할 일이 샌다** | 여러 개를 물었는데 일부만 답함. LLM이 사용자에게 시킨 일을 잊음 | 설문: 일부만 답함 9명 경험 |

**기존 도구의 한계**: ChatGPT의 분기, Claude의 메시지 수정은 사용자가 직접 갈라야 하고 한눈에 안 보임. BranchGPT · Conversation Tree 같은 트리 확장은 **구조만 그리고 의미는 판단하지 않음**. Tangent 같은 곁가지 창은 분기가 수동. → **대화의 의미를 읽고 판단하는 주체가 없다. 그 빈자리가 가닥이다.**

### 2-2. 대상 사용자와 사용 맥락
LLM으로 보고서 · 데이터 분석 · 발표 자료 · 코드처럼 여러 날에 걸친 긴 작업을 하는 학생과 지식노동자.

- 작업 유형: T1 자료 투입형 · T2 질문 탐색형 · T3 산출물 제작형 · T4 문제 해결형 · T5 발산형

- 설문 뒤 정리: 사용자를 **‘U1 + 보조 성향’**으로 봐요. 보조 성향은 비교형(여러 LLM) · 정리 보관형(노션 등에 옮김) · 병렬형(여러 창) · 위임형(에이전트) · 세팅형(맞춤 지시). 유형을 화면에 라벨로 보여 주지 않아요(“n% 확률로 U1” 카드는 폐기). **유형은 가닥이 다르게 움직이는 것으로만 드러나요.**

## 3. 해결안 — 가닥이 하는 일

### 3-1. 에이전트 루프 (턴마다 판단 → 필요하면 도구로 확인 → 행동)
판단은 **두 단**으로 나눠요(10/3). 다섯 단계와 그 내용은 그대로이고, 누가 맡는지만 달라져요. 프롬프트는 `docs/agent-prompt.md`.

**1단 · 분류** — 모든 턴에서 LLM 호출 한 번. 출력은 구조화 출력으로 형식을 보장해요.

1. **요청 나누기** — 메시지 하나에 요청이 여럿이면 쪼갬(질문 q · 작업 task · 수정 rev) → 캡슐 역
2. **분류** — 본류(depth 0) / 1차 곁길 / 2차 곁길, 정함(dec), 본류 복귀(ret), 이전 턴 참조(ref), 주제 전환(topic)
3. **붙일 자리** — 역 제목, 구간(seg), 노선의 어디에 이을지

**2단 · 확인** — 아래 조건이 걸린 턴에서만 돌아요. 에이전트가 도구를 골라 쓰고, 결과를 보고, 더 볼지 끝낼지 스스로 정해요.

4. **답변 점검** — 빠진 요청(open), 사용자에게 시킨 일, 요청 밖 파일 변경
5. **한마디** — 필요할 때만 먼저 말을 검 (할 일 장부에 쌓이고, 가장 중요한 하나가 카드로 뜸)

| 2단을 켜는 조건 | 에이전트가 주로 쓰는 도구 | 나오는 한마디 |
|---|---|---|
| 이 턴에서 파일이 바뀌었고, 1단이 요청보다 넓게 바뀐 것 같다고 봄 (Cursor · VS Code · Claude Code) | `get_diff` → `get_request` → 애매하면 `search_decisions` | 요청 외 변경 (unasked) |
| 새 대화가 열림 (그 프로젝트의 가장 새 대화의 첫 턴, 앞 대화에 정한 것이 있을 때) | `search_decisions` · `list_open_items` | 이어 가기 (handoff) |
| 1단이 빠진 요청 후보를 냄 | `get_request` | 빠진 요청 (missing) |

도구 네 개 (모두 가닥이 저장한 기록을 읽기만 해요)
- `get_request` — 그 턴의 요청 원문 · 나눈 요청(parts) · 답변 전체
- `get_diff` — 그 턴에서 바뀐 파일과 줄 (hook · 세션 파일이 넘긴 변경 내용. 필요하면 `git diff` — 이 보강은 아직)
- `search_decisions` — 프로젝트의 정한 것(dec)과 관련 턴 찾기
- `list_open_items` — 장부에 열려 있는 할 일

2단 규칙
- 루프는 최대 5번(초깃값, `GADAK_MAX_STEPS`). 근거를 찾지 못하면 한마디를 만들지 않아요.
- **판단 기록**: 2단이 돈 턴은 어떤 도구를 어떤 순서로 썼고 무엇을 보고 결론 냈는지 저장해요. 노선도 카드에는 넣지 않고(10/1 결정 유지) 별도 로그 페이지 `/trace`에서 봐요(가닥 창 왼쪽 아래 ‘판단 기록’). 시연 · 발표에서 에이전트 동작의 근거로 써요.
- **어느 턴을 볼지 (10/3)**: 정해 둔 개수가 아니라 위 조건으로 정해요. 1단이 같은 호출에서 후보(빠진 것 같은 요청 `parts[].open`, 요청보다 넓은 변경 `wide`)를 내고, 걸린 턴만 2단이 봐요. 보는 대화가 먼저, 그 안에서는 지금에 가까운 턴부터예요. 앞 턴이나 지난 대화까지 볼지는 에이전트가 도구로 그때그때 정해요.
- **루프를 도는 법 (10/3)**: 가닥이 루프를 돌리고 엔진에는 한 걸음씩 물어요. 지금까지 본 것을 주면 엔진이 다음 도구나 끝을 고르고(구조화 출력), 가닥이 그 도구를 돌려 본 것을 붙여 다시 물어요. 그래서 엔진(구독 · API 키)에 상관없이 루프와 판단 기록이 같아요. 마지막 걸음에서는 끝내는 것만 고를 수 있어요. 프롬프트는 `backend/prompts/investigate.txt`.
- **근거 검사 (10/3)**: 근거를 도구로 직접 보지 않은 결론(빠진 요청은 `get_request`, 요청 외 변경은 `get_diff`, 이어 가기는 `search_decisions`)과 기록에 없는 것을 가리키는 결론은 버리고, 버린 까닭을 판단 기록에 남겨요. 한마디의 버튼 · 바뀐 곳 · 다시 보낼 글은 엔진의 말이 아니라 저장된 기록으로 만들어요.
- 1단과 같은 일꾼 · 같은 호출 한도(`GADAK_MAX_CALLS`)를 써요. 1단을 기다리는 대화가 있으면 그것이 먼저예요.
- 데스크톱 앱(MCP) 입구에서는 1단을 Claude가 `record_turn`을 부르며 직접 채워요(기존대로). 2단은 같아요.

### 3-2. 할 일 장부와 한마디 (agentic의 핵심)
| kind | 라벨 | 예시 한마디 (실제 예시 데이터) | 실행 버튼 |
|---|---|---|---|
| missing | 빠진 요청 | “‘과제 안내 확인’ 답이 안 왔어요” | 다시 묻기 |
| unasked | 요청 외 변경 | “노선 선만 요청했는데 로고 심볼 굵기도 바뀌었어요” | 바뀐 곳 보기 → 원래대로 요청 |
| yours | 내가 할 일 | “Slack에 ‘확장 프로그램도 앱인지’ 아직 안 물어보셨어요” | 문의 글 보기 |
| branch | 숨은 가지 | “가지 1에서 요청한 ‘더블클릭으로 구간 열기’가 지금 가지엔 없어요” | 가져오기 |
| open | 끝나지 않은 곁길 | “영문 표기 문제가 결론 없이 남아 있어요” | 지금 정하기 |
| check | 이해 확인 | “04에서 BPM 설명을 듣고 질문 없이 넘어갔어요. 확인 문제 하나 풀어 볼까요?” | 문제 받기 |
| topic | 주제 전환 | “주제가 바뀌었어요 · 가닥 기획 → NBA 발표” | 노선 나누기 |
| repeat | 반복 질문 | “배포 질문, 9/30에 두 번 하셨어요” | 묶음으로 보기 |
| handoff | 이어 가기 | “지난 대화에서 정한 것 9개를 첫 메시지에 붙일까요?” | 요약 붙이기 |
| next | 다음 할 일 | “10/2 과제 등록이 내일이에요. 한 줄 소개를 ‘가닥’으로 확정할까요?” | 소개 확정 |

규칙
- 한 턴에 한마디 카드는 **하나**. 우선순위: missing · unasked(1) → yours · branch(2) → open(3) → check · topic · repeat(4) → handoff(5) → next(6)
- ‘나중에’를 누르면 장부에만 남고 카드는 닫힘. 같은 내용은 다시 띄우지 않음
- 실행 버튼은 기본적으로 **입력창에 글을 넣어 줄 뿐**, 보내기는 사용자가 결정(프로토타입에서는 시연을 위해 자동 전송). 입구가 입력창을 못 건드리면 클립보드로
- **승인한 종류만 자동 실행** (10/3): 사용자가 한마디 종류별로 ‘앞으로는 알아서’를 켠 것만 가닥이 직접 보내요. 주제 전환과 같은 방식(한 번 승인 → 다음부터 알아서)이에요
  - 자동으로 할 수 있는 종류는 둘뿐: **요청 외 변경 되돌리기**(unasked) · **이어 가기 요약 넣기**(handoff). 나머지는 늘 사용자가 보냄
  - 가닥이 보낸 것도 장부에 ‘가닥이 보냄’으로 남고, 종류별로 다시 끌 수 있어요
  - 입구별 방법은 4장의 ‘입구별 실행 방법’ 표. 켜고 끄는 자리와 문구는 아직 미정(11장)
  - **10/4 임시 구현**: 켜고 끄는 곳은 할 일 목록 맨 아래의 ‘가닥이 알아서 보내는 것’(두 종류가 켜짐 · 꺼짐과 함께 늘 보여요). 한마디를 직접 보내는 창의 ‘앞으로는 알아서’ 칸에서도 켤 수 있어요. 가닥이 보낸 한마디는 목록에 ‘가닥이 보냄’이 붙고 끝난 일로 보여요. 가닥은 2단이 근거(바뀐 곳)를 직접 보고 만든 한마디만 보내고, 자기가 보낸 글로 이어진 턴에는 다시 보내지 않아요
- 주제 전환을 한 번 승인하면 다음 전환부터는 묻지 않고 알아서 나눔 (적응형)

### 3-3. 그 밖의 기능
- **노선도**: 가로 노선. 곁길은 위로 비켜 서고, 끝난 곁길은 회색으로 접힘. 지난 구간은 눈금으로 접힘
- **레일**: 채팅 옆 세로 미니 노선. 스크롤하면 ‘보는 중’이 따라옴. 점을 누르면 그 대화로 이동
- **캡슐 역**: 요청이 여럿인 메시지. 칸 하나가 요청 하나, 빈 칸은 답이 빠진 요청
- **수정 대기열**: rev 요청은 바로 재생성하지 않고 모았다가 “최종본 한 번에 요청”
- **정한 것**: 프로젝트 전체의 결정 로그 (최근 순)
- **산출물 판**: 같은 파일을 v1 · v2 · … · 최신으로 묶음. 요청 외 변경이 섞인 파일 표시
- **지난 대화에서 찾기**: 프로젝트의 모든 대화에서 검색. 정한 것이 먼저, 노선도의 해당 역이 빛남
- **범위 전환**: [이 대화 | 프로젝트 전체] (U1), [이 대화 | 비슷한 대화 묶음] (매번 새 창)

### 3-4. Workflow 전후 비교 (Category C 필수)

교수님 방식(제2강 27쪽)대로 **업무 하나를 단위로 쪼개고 → 병목을 표시하고 → 가닥을 적용할 곳을 정해요.** 업무 둘을 깊게 다뤄요(10/3). 발표에서는 업무마다 전 · 후 flowchart 한 쌍과 측정 수치를 보여 줘요.

**업무 A — Cursor로 코드 · 분석 스크립트 고치기** (입구: Cursor · VS Code)

자동화 대상인 이유(제2강 28쪽): 인적 오류가 생기기 쉬운 데이터 집약적 작업. 바뀐 줄을 사람이 다 읽고 가려내야 해요.

| # | 단계 | AI 적용 전 (Agent만 씀) | AI 적용 후 (가닥) | 사람이 하는 일 |
|---|---|---|---|---|
| 1 | 수정 요청 | “식 이름만 바꿔 줘” | 같음 | 요청 |
| 2 | Agent가 파일 수정 | 요청 밖 함수 · 파일까지 바뀌기도 함 | hook이 요청 · 답 · 바뀐 줄을 가닥에 넘김 | — |
| 3 | 결과 확인 | **병목** · 바뀐 파일 전체를 diff로 훑어 요청한 것과 아닌 것을 직접 가림. 파일이 많으면 놓침 | 가닥이 요청과 diff를 대조해 **요청 외 변경만** 짚어 줌 | 짚어 준 곳만 검증 |
| 4 | 되돌리기 | **병목** · 무엇이 원래였는지 떠올려 되돌리기 요청을 직접 씀 | ‘원래대로 요청’ 한 번. 승인해 두면 가닥이 직접 보냄 | 처음 한 번 승인 |
| 5 | 다음 날 이어 하기 | **병목** · 새 Agent 대화에 지난 결정과 맥락을 다시 설명 | 새 대화가 열리면 정한 것 요약을 넣어 줌 | 넣을지 결정 |

측정: 요청 외 변경을 모두 찾는 데 걸린 시간 · 놓친 건수 · 되돌리기까지 보낸 메시지 수

**업무 B — 여러 날에 걸친 보고서 · 발표 자료 만들기** (입구: ChatGPT · Claude 웹, 불러오기)

자동화 대상인 이유(제2강 28쪽): 반복적이고 시간이 많이 드는 작업. 스크롤해 다시 읽기, 최신본 찾기, 맥락 옮겨 적기가 되풀이돼요.

| # | 단계 | AI 적용 전 | AI 적용 후 (가닥) | 사람이 하는 일 |
|---|---|---|---|---|
| 1 | 본 작업 질문 (개요 → 초안) | 채팅 한 줄로 쌓임 | 본류 역으로 이어짐 | 질문 |
| 2 | 곁길 질문 (용어 · 배경) | 본 작업과 섞임 | 곁길로 비켜 서고, 끝나면 접힘 | — |
| 3 | 원래 흐름으로 복귀 | **병목** · 위로 스크롤해 다시 읽거나 “아까 그거 뭐였지?” 재질문 (설문 16명 중 14명) | 레일 · 노선도의 역 클릭 | 돌아갈 역 고르기 |
| 4 | 산출물 수정 | **병목** · 지적할 때마다 v2 · v3 재생성, 요청 안 한 곳까지 바뀜 | 수정 대기열에 모았다가 최종본 한 번 요청 | 보내기 전 목록 확인 |
| 5 | 최신본 · 지난 결정 찾기 | **병목** · 폴더와 대화를 뒤지며 추측 (최신본 혼동 ‘자주 이상’ 8명) | 산출물 판의 ‘최신’, ‘정한 것’ 탭 · 찾기 | — |
| 6 | 새 대화로 옮기기 | **병목** · 맥락을 직접 요약해 붙임 (12명) | ‘이어 가기’ 한마디로 정한 것 요약 붙이기 | 붙일지 결정 |

측정: 지난 결정을 찾는 시간 · 최신본을 찾는 시간 · 새 창용 요약을 만드는 시간 · 재질문 횟수

**수치 얻는 법**: 같은 과제를 가닥 없이 · 가닥과 함께 2~3명이 해 보고 시간을 재요(순서는 사람마다 바꿈). A는 재생 모드로 고정한 요청 3건, B는 불러온 실제 긴 대화로 해요. 표본이 작다는 한계를 발표에서 같이 말해요. 수치는 측정(10/11) 뒤 이 자리에 채워요.

**기능 대응표** (어느 기능이 어느 불편에 답하는지)

| 단계 | AI 적용 전 | AI 적용 후 (가닥) |
|---|---|---|
| 곁가지 질문 | 메인 대화에 섞여 흐름을 잃음 | 자동으로 곁길로 분리, 끝나면 접힘 |
| 흐름 복귀 | 스크롤 올려 다시 읽기, “아까 그거 뭐였지?” 재질문 | 레일 · 노선도의 역 클릭 |
| 여러 요청 중 일부 누락 | 사용자가 알아채야 함 | 빈 칸 + “다시 묻기” 한마디 |
| 산출물 수정 | 지적할 때마다 v2 · v3, 요청 안 한 곳까지 바뀜 | 수정 대기열 → 최종본 1회 요청, 요청 외 변경 감지 |
| 최신본 찾기 | 폴더와 대화를 뒤지며 추측 | 산출물 판 탭의 ‘최신’ |
| 결정 확인 | 대화 전체 재검색 | ‘정한 것’ 탭 · 찾기 |
| 새 대화로 이동 | 직접 요약해 붙여 넣기 | 첫 화면에서 ‘요약 붙이기’ 한마디 |
| 놓친 일 | 기억에 의존 | 할 일 장부가 먼저 알려 줌 |

**측정 지표 (시연용)**: 산출물 재생성 횟수 · 원래 흐름으로 돌아가는 데 걸린 시간 · 최신 파일 찾는 시간 · 사용 토큰 · 한마디 수락률 · 분류 정확도(depth · dec)

## 4. 입구 네 가지

모든 입구는 **같은 백엔드 + 같은 화면 컴포넌트(가로 노선도 · 할 일 목록 · 한마디)**를 쓰고, **대화를 읽는 방법**과 **접힌 모양**만 달라요. 이것이 D안(평소엔 접힘 → 펼치면 가로 노선도)의 입구별 해석이에요.

| 입구 | 대상 | 읽는 방법 | 접힌 모양 | 펼친 모양 | 못 하는 것 |
|---|---|---|---|---|---|
| **웹** | claude.ai · chatgpt.com (+ Gemini) | 콘텐츠 스크립트가 DOM을 읽고 MutationObserver로 새 메시지 감지. 로그인한 탭을 그대로 읽어 별도 로그인 없음 | 채팅 옆 **세로 레일** | 채팅 위 **가로 노선도 카드** + 오른쪽 목록 | — (가장 완전한 입구) |
| **데스크톱 앱** | Claude 데스크톱 | MCP 서버. Claude가 답할 때마다 `record_turn` 도구로 기록을 넘김 (추가 API 비용 0) | Claude 창 가장자리의 **얇은 띠 창**(44px): 심볼 · 세로 미니 노선 · 할 일 수 | 노선도 **창** (자체 제목줄 “가닥 창 · 띠를 누르면 접혀요”) | 앱 화면 스크롤 · 입력. 역을 누르면 메시지 내용을 팝업으로. `record_turn` 호출은 Claude 재량이라 빠지는 턴이 있을 수 있음 |
| **VS Code** | Claude Code (· Codex · Gemini CLI) | **세션 파일 읽기**(10/3 저녁): `~/.claude/projects/<proj>/<session>.jsonl`에서 새로 붙은 줄만 읽음. 설정을 건드리지 않고 지난 대화까지 읽힘. 승인한 종류의 자동 실행에는 **공식 hooks**(`.claude/settings.json`: `UserPromptSubmit` · `Stop` · `PostToolUse` · `SessionStart`)를 같이 씀. Codex는 `~/.codex/sessions/…/rollout-*.jsonl`(같은 방식으로 읽음), Gemini CLI는 `~/.gemini/tmp/<hash>/chats/` | 하단 **상태 표시줄** 미니 노선 `●─○─● 04 최종 모델 확정 · 할 일 2` | 터미널 위 가로 노선도 패널 | 터미널 스크롤. 실행 버튼은 `terminal.sendText`로 터미널에 입력 |
| **Cursor** ★ | Cursor Agent 채팅 | **Cursor hooks** (`~/.cursor/hooks.json` 또는 `.cursor/hooks.json`): `beforeSubmitPrompt`(질문) · `afterAgentResponse`(답변) · `afterFileEdit`(파일 수정) · `stop`(끝남 · 자동 실행) · `sessionStart`(새 대화 · 맥락 넣기) · 모든 hook의 `conversation_id` · `transcript_path` | 하단 상태 표시줄 미니 노선 | **편집기 아래** 가로 노선도 (편집기 30% · 노선도 나머지) | Agent 패널 스크롤 · 입력. 실행 버튼은 **클립보드에 담아** 붙여 넣게 함. 승인한 종류는 `stop` hook으로 직접 보냄 |

- 우선순위: **ChatGPT 웹 → Cursor → Claude 웹 → Claude 데스크톱 MCP → VS Code(Claude Code)**. ChatGPT가 주력 11명, Cursor는 교수님 강조. 발표에서 보여 주는 비중은 이 순서 그대로예요.
- **만드는 순서 (10/3)**: Cursor → VS Code(Claude Code) → ChatGPT 웹 → Claude 웹 → Claude 데스크톱 MCP. Cursor와 VS Code는 hook 스크립트 하나를 같이 쓰고 공식 hooks라 가장 먼저 끝낼 수 있어요. 입구 넷은 모두 만들어요.
- **Cursor가 산출물 문제(C)와 가장 잘 맞아요.** `afterFileEdit` + `git diff`로 요청 외 변경을 추측이 아니라 실제로 잡을 수 있어요. 대표 시연 장면 후보.
- **ChatGPT 데스크톱 앱 · 모바일 앱은 읽을 수 없어요.** 발표에서 한계로 밝혀요.
- Cursor Cloud Agent에서는 `afterAgentResponse` · `stop` hook이 안 돈다는 버그 보고가 있어요. 로컬 Agent 기준으로 만들어요. 공식 문서에 따르면 Cloud Agent에서는 `sessionStart`도 돌지 않아요.
- VS Code/Cursor 상태 표시줄(StatusBarItem)은 **텍스트와 codicon만** 돼요. 프로토타입의 SVG 미니 노선 대신 `●─○─●` 같은 문자로 그려요.
- 여러 LLM을 묶는 ‘비교 갈래’는 만들지 않아요(불편 근거 없음). 기록이 한 저장소에 모이니 같은 프로젝트의 ChatGPT 대화와 Claude 대화가 한 노선도에 놓이는 정도만 지원해요. 발표에서는 “가닥은 서비스를 가리지 않는다” 한 줄.
- **켜면 알아서 (10/3 저녁)**: 사용자가 입구마다 설정하지 않아요. 가닥을 켜면 이 PC에서 무엇을 쓰는지 찾아서(`backend/sources/`) 읽을 수 있는 것을 읽어요. ① 기록 파일이 PC에 남는 것(Claude Code · Codex)은 알아서, 지난 대화까지. ② Cursor는 가닥 창에서 ‘연결’ 한 번(사용자 hook을 붙임), 그 뒤 대화부터. ③ 웹의 채팅은 크롬 확장을 한 번 넣으면 그 뒤로 연 대화를 읽어요(10/4). 한 번도 열지 않은 지난 대화와 데스크톱 앱의 채팅은 내보내기 파일로, Claude 데스크톱은 MCP가 생기면 그쪽으로. 무엇을 찾았는지는 가닥 창의 ‘찾은 곳’에 보여요.
- **구현 1차 화면 (10/3)**: Cursor · VS Code · 데스크톱 앱에서는 표의 접힌 · 펼친 모양(상태 표시줄, 편집기 아래 패널, 띠 창)을 바로 만들지 않고, 백엔드가 내주는 **로컬 웹 페이지**(`http://127.0.0.1:7311`, ‘가닥 창’)에 같은 노선도 카드를 띄워요. 가닥 창은 왼쪽에 프로젝트 · 대화 목록, 위에 노선도 카드, 아래에 그 대화(읽기 전용)와 레일이 있는 모양이에요(프로토타입 웹 입구에서 브라우저 틀과 입력창을 뺀 것). macOS에서는 가닥 앱이 이 페이지를 자기 창에 띄워요(10/4). 앱이 없으면 브라우저 창으로 열어 Cursor 옆에 두고 써요. 표의 모양은 디자인 목표로 그대로 두고, 여유가 있을 때 확장(.vsix)과 띠 창으로 옮겨요. 웹 입구는 표 그대로(레일 + 카드)예요.
- **불러오기 (다섯 번째 경로, 10/3)**: ChatGPT · Claude의 대화 내보내기 파일을 `/import`로 올리면 같은 노선도가 그려져요(가닥 창의 찾은 곳 → 파일 고르기). 내 PC의 가닥에서 측정(3-4의 B)에 쓰고, 실시간 입구가 못 읽은 대화를 채워요. 배포 웹 데모에서는 쓰지 않아요.
- **웹 입구의 읽기 (10/4)**: 매번 내보내기를 하지 않게, 표의 웹 입구 중 ‘읽는 방법’을 먼저 만들었어요. 확장의 콘텐츠 스크립트가 열어 둔 대화의 화면을 읽어, 지금 보이는 질문 · 답의 목록을 `/pages`로 통째로 보내요. 가닥이 그 목록을 저장소의 역과 맞춰요 — ChatGPT는 화면의 메시지 id로, id가 없는 Claude는 질문 글과 그 글이 나온 차례로. 그래서 같은 대화를 다시 열어도, 내보내기 파일로 먼저 넣은 대화여도 겹치지 않아요. 열어 보기만 한 지난 대화는 빈 곳만 채우고 바로 정리하지 않아요(가닥 창에서 볼 때 정리 · 구독 한도). 지켜보는 동안 새로 끝난 턴만 정리 줄에 서요. 답이 오는 중인 턴은 한 번, 다 온 뒤에 한 번 더 보내요. 임시 채팅 · 시크릿 채팅 · 시크릿 창은 읽지 않고, 확장 아이콘의 팝업에서 읽기를 끌 수 있어요. 화면은 읽기만 하고 고치지 않아요. 레일 · 노선도 카드 붙이기와 입력창에 넣기는 10/8–9. **실제 사이트 화면에서는 아직 확인 전**이라, 안 읽히면 팝업의 ‘진단 복사’(화면의 뼈대만 · 글 없음)를 받아 `extension/content/sites/*.js` 위쪽의 셀렉터를 고쳐요.

**입구별 실행 방법** (3-2의 ‘승인한 종류만 자동 실행’)

| 입구 | 기본 (사용자가 보냄) | 승인한 종류 (가닥이 보냄) |
|---|---|---|
| 웹 | 입력창에 글을 넣어 줌 | 글을 넣고 전송까지 |
| Cursor | 클립보드에 담음 | `stop` hook이 `followup_message`를 돌려줌(반복 한도 기본 5회). 새 대화의 요약은 `sessionStart`의 `additional_context` |
| VS Code (Claude Code) | 클립보드에 담음 (확장을 만들면 `terminal.sendText`) | `Stop` hook이 `decision: "block"` + `reason`을 돌려줌. 새 세션의 요약은 `SessionStart`의 `additionalContext` |
| 데스크톱 앱 | 클립보드에 담음 | 없음 (MCP로는 사용자 대신 보낼 수 없음) |

- **10/4 구현 상태**: Claude Code와 Cursor의 ‘승인한 종류’ 칸을 만들었어요(`backend/auto.py` · `cursor-hooks/gadak-hook.py`). **Claude Code는 실제로 확인**했어요 — 새 대화가 시작될 때 넣은 요약을 모델이 알고 답하고, 턴이 끝날 때 돌려준 글을 이어서 실행하고, 그 뒤에는 다시 보내지 않아요. Cursor의 `followup_message` · `additional_context`는 문서대로 만들었지만 실제 Cursor에서는 확인 전이에요. 웹은 확장이 입력창을 다루게 된 뒤(10/8–9)예요.
- **Claude Code에서는 hook 둘이 필요해요**: 대화는 기록 파일로 읽지만(설정을 건드리지 않음), 가닥이 직접 보내려면 `Stop` · `SessionStart` hook을 Claude Code 설정(`~/.claude/settings.json`)에 더해야 해요. 가닥 창의 **찾은 곳 → 자동 실행 연결**을 사용자가 눌렀을 때만 더하고, 있던 설정은 그대로 두며, 고치기 전 파일을 옆에 남겨요. 같은 자리에서 뗄 수 있어요.
- **턴이 끝날 때 기다려요**: 요청 외 변경은 1단 · 2단이 끝나야 알 수 있어서, 승인을 켜 둔 경우 **파일이 바뀐 턴**에서는 hook이 가닥의 확인을 최대 40초 기다려요(실제 엔진으로 잰 한 번은 약 25초). 승인을 켜지 않았거나 파일이 안 바뀐 턴은 바로 지나가요.

## 5. 시스템 구조

```
[claude.ai / chatgpt.com]──콘텐츠 스크립트──┐
[Claude 데스크톱]──MCP record_turn─────────┤
[Claude Code · Codex]──세션 파일 읽기──────┼──► 백엔드 (Python · Flask, 로컬 127.0.0.1:7311)
[Cursor Agent]──hooks.json → gadak-hook.py─┘        ├─ agent/ : 1단 분류(매 턴 LLM 1회) + 2단 확인(조건부 도구 루프) + 판단 기록
                                                     ├─ search/ : 문자열 + 임베딩 (repeat · 찾기)
                                                     ├─ sources/ : 내 PC의 기록 찾기 · 읽기 (켜면 알아서)
                                                     └─ store.py : SQLite
        ◄── 노선도 · 할 일 · 한마디 데이터 ── 각 입구의 화면 (shared/ui, 프로토타입에서 옮김)
            웹: Shadow DOM에 레일 + 카드 · Cursor · VS Code · 데스크톱 앱: 로컬 웹 페이지(같은 백엔드가 내줌)

[대화 내보내기 파일]──/import──► 같은 백엔드 (불러오기 · 10/3)
백엔드 ──사용 기록(동의한 사용자만 · 숫자와 정해 둔 낱말만)──► [가닥 팀 서버 server/] ──► 통계 화면 (10/4)
[배포 웹 데모] = 같은 화면. 실시간 입구도 LLM 호출도 없이, 미리 분류해 둔 예시 대화만 보여 줌 (제출 링크 · 10/3)
```

**10/3에 더한 구현 규칙**
- **턴 중복 방지**: 같은 `chat.id` + `messageRef`가 다시 오면(새로고침 · hook 재실행) 새 역을 만들지 않고 덮어써요.
- **화면 갱신**: 로컬 웹 페이지는 1.5초마다 `/status`의 변경 번호(rev)를 보고, 바뀌었을 때만 `/view`를 다시 불러와요. 웹 확장은 화면을 붙일 때(10/8–9) 보낸 응답을 받아 바로 그려요.
- **기록 읽기 (10/3 저녁)**: `backend/sources/`가 기록 파일을 찾아, 지난번 이후로 붙은 줄만 2.5초마다 읽어요. 읽는 곳마다 파일 형식만 다르고(`claude_code.py` · `codex.py` · `exports.py`), 저장소에 옮기는 방법은 하나예요(`sync.py`). 가닥이 꺼져 있던 동안 hook이 쌓아 둔 이벤트도 켤 때 같이 넣어요.
- **보는 대화부터 정리 (10/3 저녁)**: 지난 대화를 한꺼번에 분류하지 않아요. 화면에 보이는 대화와 새로 끝난 턴만 줄을 세워 하나씩 분류하고, 한 대화의 턴을 8개씩 묶어 한 번에 물어요(구독 한도 · 시간). 화면에는 원문의 앞부분만 보내고(질문 600자 · 답 700자), 전체는 역을 열 때 받아요.
- **hook 스크립트 하나**: Cursor와 Claude Code가 `cursor-hooks/gadak-hook.py`를 같이 써요. 받은 JSON 모양만 어댑터 둘로 맞춰요.
- **hook 이벤트는 `/events`로**: hook은 질문 · 파일 수정 · 답변을 따로따로 보내요. 백엔드가 같은 대화 · 같은 질문끼리 모아 Turn 하나로 만들어요. 완성된 턴을 하나씩 보내는 입구는 `/turns`, 화면을 통째로 보내는 웹 확장은 `/pages`(10/4).
- **엔진**: 가닥이 판단에 쓰는 LLM은 `backend/engines/`에서 갈아 끼워요. 지금은 Claude 구독 엔진(`claude_cli`)과 엔진 없음(`none`). 고르는 법은 `docs/usage-guide.md`.
- **재생**: 저장해 둔 hook 입력이나 예시 대화를 같은 경로로 다시 흘려보내요(`backend/replay.py`). 정확도 평가 · 측정 · 데모 백업에 써요.
- **배포 웹 데모**: 미리 분류해 둔 예시 대화만 보여 줘요(10/3 결정). LLM을 부르지 않아서 API 키도 비용도 없어요. 방문자가 자기 대화를 올리는 기능은 넣지 않아요. 예시는 만든 대화로 준비해요(실제 대화는 공개하지 않음).
- **2단 (10/3 밤)**: 1단 호출이 후보를 같이 내고(`turns.look`), 걸린 턴만 같은 일꾼이 이어서 확인해요. 할 일은 `items`, 판단 기록은 `agent_runs`에 남고, 화면은 `/view`의 `todo` · `parts[].open`으로 프로토타입 그대로 그려요. 1단의 후보(`parts.open` = 2)는 2단이 확인하기 전까지 화면에 보내지 않아요.
- **사용 기록 (10/4)**: 가닥을 어떻게 쓰는지를 PC에 적어 두고(`backend/usage.py`), 사용자가 동의하면 가닥 팀 서버(`server/`)로 보내요. 적을 수 있는 이름과 칸은 `backend/usage_schema.py`의 표가 전부이고, 값은 숫자 · 참거짓 · 정해 둔 낱말뿐이에요. 글이 들어갈 칸이 없어서 대화 내용은 실수로도 실리지 않고, 서버도 같은 표로 한 번 더 걸러요. 동의하기 전에 적힌 기록은 보내지 않아요. 누가 보냈는지는 무작위 설치 번호로만 알고, 사용자는 언제든 끄고 서버의 자기 기록을 지울 수 있어요. 서버 주소(`GADAK_COLLECT_URL`)가 없으면 묻지도 보내지도 않아요. 모은 기록을 어떻게 읽고 무엇을 고치는 데 쓰는지는 `docs/changes-detail.md` 13번.
- **웹 확장은 `/pages`로 (10/4)**: 웹 화면에서는 턴을 하나씩 받을 수 없고(지난 대화를 열면 한꺼번에 보이고, Claude 화면에는 메시지 id가 없어요), 내보내기 파일로 넣은 대화와도 맞춰야 해서, 확장은 보이는 대화를 통째로 보내고 맞추기는 가닥이 해요(`backend/sources/pages.py`). 맞추는 차례는 메시지 id → 질문 글 + 같은 글 중 몇 번째. 화면에서 읽은 지난 턴은 이미 있는 답을 덮어쓰지 않고(내보내기 파일의 글이 원문), 지켜보는 동안 달라진 답만 고쳐 쓰고 다시 정리해요. 주소만 먼저 바뀌고 화면은 앞 대화 그대로인 순간에는 보내지 않아요(확장이 기다리고, 가닥도 같은 메시지 id가 다른 대화에 있으면 받지 않아요). **확장이 보내는 곳은 내 PC의 가닥(127.0.0.1:7311) 하나뿐**이고, `tests/test_extension.py`가 코드에 다른 주소나 다른 보내는 길이 없는지 확인해요.
- **자동 실행 (10/4)**: hook이 턴이 끝날 때 `POST /auto/stop`, 새 대화가 시작될 때 `POST /auto/start`로 “이어서 보낼 글이 있나요?”를 물어요. 가닥은 승인한 종류에 대해서만 답해요 — 끝난 턴에 2단이 확인한 열린 ‘요청 외 변경’이 있으면 그 한마디의 ‘원래대로’ 글을, 같은 프로젝트의 지난 대화에 정한 것이 있으면 이어 가기 요약을 돌려줘요. 보낸 것은 `auto_log`에 남고(각자 PC에만), 한마디는 끝난 일로 바뀌며 `sent: "auto"`가 붙어요. 되풀이를 막는 것은 셋: 도구가 알려 주는 ‘이어진 턴’ 표시(`stop_hook_active` · `loop_count`), 가닥이 보낸 글로 시작한 턴인지, 이미 보낸 한마디인지. 승인은 `POST /auto {kind, on}`으로 켜고 끄고, 자동으로 할 수 있는 종류는 코드에 둘로 박혀 있어요(`store.AUTO_KINDS`).
- **다시 켜면 새 코드 (10/4)**: 켤 때 이미 켜져 있는 가닥이 있으면 붙기 전에 코드를 견줘요(`/health`의 `code` = 백엔드 코드를 마지막으로 고친 때). 다르면 그 가닥을 끄고(화면의 ‘끄기’와 같은 길) 지금 코드로 다시 켜요. 같으면 전처럼 그대로 붙어요. 전에는 터미널 등에서 먼저 켜 둔 가닥이 남아 있으면 앱을 껐다 켜도 예전 코드가 계속 돌았어요.
- **대화 찾기 (10/4)**: 가닥 창 왼쪽 위의 칸. `/chats/search?q=`가 모든 프로젝트의 대화에서 찾아요 — 대화 제목 · 프로젝트 이름 · 쓴 곳(ChatGPT · Cursor …)이 맞는 대화가 먼저, 그다음 글이 맞는 대화(맞은 턴 하나와 그 둘레 글), 그 안에서는 최근에 쓴 대화가 위. 누르면 그 대화의 그 턴으로 가요. 노선도 카드 안의 ‘지난 대화에서 찾기’(7-9)는 그대로 그 프로젝트 안에서 턴을 찾아요.
- 이 규칙들을 데이터 계약(`docs/schema.md`)에 넣는 건 기획 담당 확인 뒤예요. 제안은 `docs/changes-detail.md` 4번 · 8번 · 11번 · 12번.

### 5-2. Git 협업 규칙
1. `main`은 항상 시연 가능한 상태. 직접 push 금지
2. 기능마다 브랜치: `feat/shared-ui-map`, `feat/ext-chatgpt`, `feat/cursor-hooks`, `docs/readme`
3. 커밋 메시지: `feat:` `fix:` `docs:` `refactor:` + 한 줄 한국어
4. PR을 열고 상대가 확인 뒤 merge. **화면이 바뀌는 PR은 프로토타입과 나란히 찍은 스크린샷 첨부**
5. `docs/schema.md` · `prototype/` · `backend/prompts/`는 손대기 전에 한마디 (기획 담당)
6. `.env`는 `.gitignore`. 대화 원문이 든 DB 파일도 커밋 금지. 설문 원자료(`docs/survey/*.xlsx`)도 올리지 않아요 — 응답자에게 “익명이며 과제 분석에만 써요”라고 안내했어요(10/3)

### 7-2. 이름과 말투
- 이름 **가닥** — “가닥을 잡다(흩어진 생각의 방향을 잡다)” + 실 한 가닥(심볼의 선). 이전 이름 ‘갈래’는 “갈래 말래”처럼 들려 폐기, 후보 ‘갈피’는 크롬 웹스토어에 같은 이름 확장이 있어 탈락

- 말투: 해요체, 한 줄, 동사는 짧게. 사용자 쪽 말로 (“세그먼트” 대신 “구간”, “노드” 대신 “역”)

### 7-6. 가로 노선도 그리는 법 (`renderMap`)
- 높이: 구간이 여럿이면 위 34px(구간 이름 줄), 아니면 22px. 본선 y = 위 + 64. 1차 곁길 y = 본선 − 36, 2차 = 본선 − 62. 전체 높이 = 본선 + 82.
- 좌우 여백 64px. 역 간격 `step` = clamp(구간 여럿이면 96 · 아니면 108, (폭 − 여백 − 접힌 눈금 − 구간 틈) / 펼친 간격 수, 150).
- 접힌 구간: 역 간격 18px(그 구간 역이 12개 넘으면 7px). 구간 경계 틈: 펼침→펼침 +22, 펼침→접힘 +24, 접힘→펼침 +0.55 step, 접힘→접힘 +44. 접힌 구간도 이름 글자 폭(실측) + 22px보다 좁아지지 않게.
- 노선이 카드보다 짧으면 가운데 정렬. 길면 가로 스크롤 + 양끝 24px 흐림 마스크, 펼칠 때 ‘지금’ 역이 오른쪽 70% 지점에 오게 스크롤.
- **본선**: 4.5px, 둥근 끝, `--fg`. 프로젝트 전체 보기에서는 대화마다 따로 긋고 사이를 `--ring` 2.5px 점선(`0.1 7`)으로 이음.
- 지금 위치가 곁길에 있으면 본선 끝에 점선 꼬리(3.5px, `0.1 8`, 길이 0.8 step) — “본류는 멈춰 있음”.
- **곁길**: 갈라진 역 +18px에서 출발해 비스듬히(가로 = 높이 차 × 0.76) 올라간 뒤 수평. 1차 끝 x = max(출발 + 비스듬 + 16, 역 + 0.62 step), 2차는 그 뒤 +8 → 비스듬 → +14. 진행 중이면 `--muted` 3px, 끝났으면 `--ring`(2차 `--stem`) 2.5px. 층마다 점 하나(진행 중이면 지금 위치, 끝났으면 마지막). 곁길이 2개 이상이면 끝에 개수.
- **숨은 가지(고쳐 쓴 메시지)**: 역 위로 `--ring` 2px 점선(`4 4`) 반원(폭 ±min(34, 0.32 step), 높이 30) + 가지마다 점선 점. 반원 위에 “가지 3”.
- **참조(ref) 연결**: 본선 아래 12px에서 시작하는 `--accent` 1.5px 점선(`2 4`) 곡선, 가운데가 30px까지 처짐.
- 라벨: 역 아래 20px, 폭 step − 14, 제목 한 줄(줄바꿈 균형), 아래에 `■ n · vK`, 묶음 보기에서는 날짜.
- 구간 이름 버튼: 구간 첫 역 x − 8, 위 4px. 접힌 구간은 `이름 n ▸`(흐린 색). 누르면 펼침/접힘.

### 7-7. 구간 접기 · 펼치기
- 처음에는 **지금 구간만 펼침** (역이 9개 이하면 모두 펼침).
- 다음 턴이 새 구간(seg · 승인된 topic)을 시작하면 지난 구간이 **저절로 접히고**, 새 구간 역이 차례로 튀어나옴.

### 7-9. 노선도 카드 (모든 입구 공통, `mountDrawer`)

- 할 일 항목: 묶음 ‘놓친 일’(빨간 고리) · ‘제안’(점선 고리), 최근 것이 위. 한 줄 `출처 역 · 라벨`, 본문(누르면 그 위치로), 버튼 [실행(검정)] [나중에]. 처리한 항목은 점선 테두리 + 취소선. 새로 생긴 항목은 아래에서 8px 올라옴.

## 10. 구현 순서와 일정 (10/3 다시 잡음)
